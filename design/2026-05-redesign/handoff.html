Using this with Claude Code

How to feed this redesign to Claude Code so nothing gets lost

Claude Code reads both HTML and PNGs. The bundle this doc lives in contains everything it needs: the doc, the interactive prototype, and the screenshots/ folder. Three ways to hand it over:

Option 1 · Push the redesign assets to a branch in the same repo (preferred)

Drop this whole project folder into fermi-viewer/design/2026-05-redesign/ on a feature branch, commit, then point Claude Code at it:

Tips that materially improve hand-off quality

  • Phase the work. Don't ask for the whole redesign in one shot. Ask for Phase 1, review the PR, then Phase 2. Each phase ships behind a green test suite.
  • Pin the screenshots. When asking for a specific region (e.g. capture banner), attach the relevant screenshot inline so Claude Code anchors to it.
  • Restate the contracts. Mention the size ratchet, the workshop pattern, and the "no external toolboxes" rule in your prompt — they're in CLAUDE.md but worth repeating.
  • Use the live prototype. The interactive prototype answers "what should this look like on hover?" / "what does the active state look like?" — open it side-by-side while reviewing PRs.
  • Track open questions. Section 13 lists 5 design decisions that should be resolved before implementation, not during.

Summary

Variant A keeps the existing 3-pane SDI mental model — image list left, image stage center, tools panel right. The redesign tightens chrome (9 menus → 6, deduped against the workbar), promotes the capture-mode UX from "barely visible" to a first-class amber banner, replaces the 4-tab × 40-button right panel with collapsible sections, and adds a status bar + ⌘K command palette.

None of these change the underlying functional layers (parser → process → display) or the workshop pattern. Every change is at the chrome / view-builder layer, which is where the package functions already live.

Phased rollout

Three phases. Each lands behind a green test run.

Token refresh + cosmetic chrome

Pure swap-in. No layout changes, no new files.

  • Refresh +fermiViewer/+chrome/uxTokens.m with the new dark/light palette
  • Update buttonPalette.m tool/primary/danger colors
  • Trim buildMenuBar.m from 9 → 6 menus (dedupe vs toolbar)

Ratchet impact: net negative (menu items removed).

Right panel + status bar

  • Replace buildTransformPanel.m's 4-tab uitabgroup with a collapsible-section scrollable container (see §6)
  • Add +fermiViewer/buildStatusBar.m as a new bottom row (1×N grid hosting x,y / I / cal / zoom / mode readout)
  • Refine buildSingleViewPanel.m's in-axes toolbar group separators (cosmetic)
  • Image-list cell renderer: thumbnail dimensions + accent rail (callbacks in FermiViewer.m)

Ratchet impact: buildTransformPanel shrinks substantially (no nested tabs); buildStatusBar is a new ~80-line package function so net is roughly zero in FermiViewer.m.

Capture-mode banner + ⌘K palette

  • Add +fermiViewer/+chrome/captureBanner.m — overlay panel that listens to appData.captureMode and renders itself on top of the uiaxes
  • Mirror the banner state in the new status bar
  • Add +fermiViewer/buildCommandPalette.m — modal uipanel with a uieditfield, uilistbox of actions, ⌘K shortcut registered via fig.WindowKeyPressFcn

Ratchet impact: both are new package functions; dispatcher inside FermiViewer.m is one or two lines per hook. Net < 10 lines.

Alpha caveat. uifigure components don't accept RGBA backgrounds. Wherever the redesign uses oklch(... / 0.X) (e.g. capture-banner background, selected image-cell tint), composite the alpha against the parent surface and store the pre-composited RGB.

5 · Capture-mode banner

+fermiViewer/+chrome/captureBanner.m (new)
The headline UX fix. An overlay panel pinned to the top-center of the uiaxes that mirrors appData.captureMode with an amber pill, animated dot, step counter, and Esc affordance.
new

MATLAB uifigure can't truly overlay a uipanel on top of a uiaxes in CSS-positioned absolute fashion, but we can fake it with a zero-grid-row uipanel that uses Position in pixels and a parent of the same uigridlayout cell as the uiaxes. The trick: parent the banner uipanel to the same grid cell as the uiaxes; pixel-position it inside that cell.

function banner = captureBanner(parentCell, tk)
%CAPTUREBANNER  Build the capture-mode overlay banner.
%
% parentCell — uigridlayout cell that hosts the uiaxes (Row/Col).
% tk         — fermiViewer.chrome.uxTokens(theme)
%
% Returns a banner struct:
%   banner.panel        uipanel  (the overlay — Visible='off' by default)
%   banner.lblLabel     uilabel  ("Distance")
%   banner.lblStep      uilabel  ("STEP 1/2")
%   banner.lblHint      uilabel  ("Click point A")
%   banner.update(mode, stepIdx)   function handle

    banner.panel = uipanel(parentCell, ...
        'BorderType',    'line', ...
        'HighlightColor', tk.capture, ...
        'BackgroundColor', tk.captureBg, ...
        'AutoResizeChildren', 'off', ...
        'Visible', 'off');
    % Banner is fixed-position. The host axes panel will pin it to the
    % top-center via a sizeChangedFcn on the parent.
    banner.panel.Position = [0 0 440 36];

    rowGL = uigridlayout(banner.panel, [1 5], ...
        'ColumnWidth', {10, 'fit', 'fit', '1x', 'fit'}, ...
        'Padding', [10 6 10 6], 'ColumnSpacing', 8);

    % animated dot — uses a uiimage with a 6-frame APNG. If we don't have
    % the APNG yet, a static colored uipanel is fine for v1.
    dot = uipanel(rowGL, 'BackgroundColor', tk.capture, 'BorderType', 'none');
    dot.Layout.Column = 1;

    banner.lblLabel = uilabel(rowGL, 'Text', '', ...
        'FontColor', tk.capture, 'FontWeight', 'bold');
    banner.lblStep  = uilabel(rowGL, 'Text', '', ...
        'FontColor', tk.captureBg, 'BackgroundColor', tk.capture, ...
        'FontName', 'Consolas', 'FontSize', 10, ...
        'HorizontalAlignment', 'center');
    banner.lblHint  = uilabel(rowGL, 'Text', '', 'FontColor', tk.capture);

    escLbl = uilabel(rowGL, 'Text', 'Esc', ...
        'FontName','Consolas', 'FontSize',10, ...
        'FontColor', tk.capture);

    % update closure — pure function that takes the dispatch table.
    captureModes = fermiViewer.captureModeTable();   % see §10
    banner.update = @(mode, stepIdx) localUpdate(banner, captureModes, mode, stepIdx);
end

function localUpdate(banner, table, mode, stepIdx)
    if strcmp(mode, 'none')
        banner.panel.Visible = 'off';
        return;
    end
    m = table.(mode);
    banner.panel.Visible = 'on';
    banner.lblLabel.Text = m.label;
    banner.lblStep.Text  = sprintf('STEP %d/%d', stepIdx, numel(m.steps));
    banner.lblHint.Text  = m.steps{stepIdx};
end

Wire the banner into buildSingleViewPanel: parent it to the same axGL row that holds the uiaxes, position via SizeChangedFcn on axGL to keep it centered 16 px from the top.

Collapsible-section helper

MATLAB uipanel with a TitleBarColor + a uibutton(state) for the chevron isn't quite native, but we can fake it with a uigridlayout that has a clickable header row + a content row whose RowHeight goes to 0 when collapsed.

function sec = section(parent, tk, title, collapsedDefault)
%SECTION  Build a collapsible right-panel section.
    sec.outerGL = uigridlayout(parent, [2 1], ...
        'RowHeight', {26, 'fit'}, 'Padding', [0 0 0 0], 'RowSpacing', 0);

    sec.header = uibutton(sec.outerGL, ...
        'Text', ['▾  ', upper(title)], ...
        'HorizontalAlignment', 'left', ...
        'BackgroundColor', tk.surface1, ...
        'FontColor', tk.textDim, ...
        'FontWeight', 'bold', ...
        'FontSize', 10);
    sec.header.Layout.Row = 1;

    sec.body = uigridlayout(sec.outerGL, [1 1], ...
        'Padding', [14 6 14 12], 'RowSpacing', 6);
    sec.body.Layout.Row = 2;

    sec.collapsed = collapsedDefault;
    sec.header.ButtonPushedFcn = @(~,~) toggleSection(sec);
    if collapsedDefault
        sec.outerGL.RowHeight = {26, 0};
        sec.header.Text = strrep(sec.header.Text, '▾', '▸');
    end
end

Section content

The five Image-mode sections, in order:

  1. Contrast — Auto / Reset buttons; colormap dropdown; histogram (uiaxes); Low / High sliders; γ / linear / CLAHE tag row
  2. Measurements — 3×2 grid of capture-mode tiles (Profile / Distance / Angle / Polyline / ROI / Crop); live result card below
  3. Filters — 3×2 grid (Gaussian / Median / CLAHE / Sharpen / FFT mask / Threshold); filter-stack indicator
  4. Annotations — Text / Arrow / Circle / Scale bar (collapsed by default)
  5. Export — Save / Copy / With overlays / Batch (collapsed by default)

The Measurement tile is the visual workhorse — when its capture mode is the active one, its background becomes tk.captureBg and border tk.capture. Mirrors the banner color.

8 · Command palette

+fermiViewer/buildCommandPalette.m (new)
⌘K-triggered modal that lets users search every action. Discoverability + power-user speed in one widget.
new

Implementation outline:

  1. A child uifigure with WindowStyle = 'modal' and a single uipanel sized 560 × 420 centered on the parent. (MATLAB modal uifigures sit on top of the main window and capture focus — closer to a real palette than a uipanel overlay.)
  2. Top: uieditfield with placeholder "Search every action…" and a ValueChangingFcn that filters.
  3. Body: uilistbox showing matched items grouped by category (use Unicode bullets / spacing for headers).
  4. Bottom keyboard hint row.
  5. Each item dispatches via the same callback struct (cb) that buildMenuBar uses — single source of truth for the action registry.
function palette = buildCommandPalette(parentFig, tk, cb)
    palette.fig = uifigure('Name', '', ...
        'WindowStyle',    'modal', ...
        'Resize',         'off', ...
        'Color',          tk.surface1, ...
        'Visible',        'off', ...
        'Position',       centerOn(parentFig, 560, 420));

    gl = uigridlayout(palette.fig, [3 1], ...
        'RowHeight', {44, '1x', 32}, 'Padding', [0 0 0 0]);

    palette.search = uieditfield(gl, ...
        'Placeholder', 'Search every action…', ...
        'BackgroundColor', tk.surface1, ...
        'FontColor', tk.text, ...
        'FontSize', 16);
    palette.search.ValueChangingFcn = @(s,e) refilter(palette, registry, e.Value);

    palette.list = uilistbox(gl, ...
        'BackgroundColor', tk.surface1, ...
        'FontColor', tk.text);
    palette.list.ValueChangedFcn = @(s,e) dispatch(palette, registry, e.Value, cb);

    palette.show = @() showPalette(palette);
    palette.hide = @() set(palette.fig, 'Visible', 'off');
end

Register the shortcut from FermiViewer.m:

fig.WindowKeyPressFcn = @(~,e) handleGlobalKey(e, palette);

function handleGlobalKey(e, palette)
    if any(strcmp(e.Modifier, 'command')) || any(strcmp(e.Modifier, 'control'))
        if strcmp(e.Key, 'k')
            palette.show();
        end
    end
end

9 · Image list cells

The current uitable-style image list shows just the filename. Upgrade to a custom cell renderer — each row is a uipanel with:

  • 38 × 38 thumbnail (cached via imaging.generateThumbnail)
  • Filename in tk.textDim (active row: tk.text)
  • Subtitle in tk.textFaint, monospace, format: WxH · pixelSize · voltage
  • 2-pixel-wide accent rail on the left when active

This is the only place where v1 deviates from a vanilla uitable contract. Two options:

  1. Easy. Keep the uitable, swap its FontSize and tint the active row via StyleConfigurations. Loses the thumbnail.
  2. Right. Replace with a uigridlayout with N rows of {38} each, hosting per-row uipanels. uigridlayout can hold an arbitrary number of rows via RowHeight = repmat({38}, 1, N); wrap in a uiscrollbar-style outer uipanel for overflow.

10 · State plumbing

Two new pieces of state live on appData:

  • appData.captureModeStep — int, current step within the capture-mode workflow. Incremented inside the mouse-down handler for each capture mode.
  • appData.theme — already exists.

The capture-mode dispatch table — pull it out of inline strings into a single source of truth:

% +fermiViewer/captureModeTable.m
function tbl = captureModeTable()
    tbl.profile  = struct('label','Line Profile',  'steps',{{'Click start point','Click end point'}});
    tbl.distance = struct('label','Distance',      'steps',{{'Click point A','Click point B'}});
    tbl.angle    = struct('label','Angle (3-pt)',  'steps',{{'Click vertex','Click ray 1','Click ray 2'}});
    tbl.polyline = struct('label','Polyline',      'steps',{{'Click to add points','Double-click to finish'}});
    tbl.roi      = struct('label','ROI Statistics','steps',{{'Drag to draw rectangle'}});
    tbl.crop     = struct('label','Crop',          'steps',{{'Drag to draw region','Enter to apply'}});
    tbl.zoom     = struct('label','Zoom Box',      'steps',{{'Drag to draw zoom region'}});
end

Both captureBanner.update and buildStatusBar.update consume this table. Add a hook to your mouse-down handler in interaction.mouseOps that bumps captureModeStep and refreshes both. Esc clears the mode and hides the banner (already wired through handleEscKey nested function).
